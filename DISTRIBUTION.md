# Выпуски через GitHub

Проект подготовлен для бесплатного распространения без Apple Developer Program. Пользователь скачивает DMG, переносит ControlFlip в «Программы», подтверждает первый запуск и выдаёт Универсальный доступ. Собственный сертификат на его Mac устанавливать не требуется.

## Постоянная подпись автора

Все версии должны подписываться одним ключом автора с неизменным `CFBundleIdentifier` (`local.controlflip.mac`). Не создавайте новый сертификат для каждого релиза. Файл `author.p12` и его пароль храните вне публичного проекта, с защищённой резервной копией. Ключ, уже созданный для текущего проекта, нужно повторно использовать.

Если ключа ещё нет, выполните один раз, выбрав закрытую папку вне репозитория:

```sh
python3 Packaging/create_author_identity.py /путь/к/закрытой-папке
```

Генерация откажется заменять существующую папку. После ошибки сборки используйте созданные файлы и повторите подготовку выпуска, а не создание ключа:

```sh
python3 Packaging/prepare_local_release.py /путь/к/закрытой-папке
```

Этот шаг выполняет проверки, сборку и упаковку подписанного DMG. Подпись формируется локально из P12 утилитой `rcodesign`, без обращения к связке ключей и без сервера подписи. Пароль читается из закрытого файла, ключ не отправляется в сеть. Загрузчик фиксирует версию инструмента и проверяет SHA-256 архива; полученное приложение дополнительно проверяется штатным `codesign` macOS. В `dist/` появятся установщик, контрольная сумма и описание подписи.

Инструмент подписи загружается при первом выпуске, поэтому автору и GitHub Actions нужен доступ к сети. Обычным пользователям он не нужен. [Документация rcodesign](https://gregoryszorc.com/docs/apple-codesign/0.29.0/apple_codesign_rcodesign_signing.html).

Самоподписанный сертификат не заменяет Developer ID и нотариальное заверение Apple. Предупреждение первого запуска ожидаемо. При переходе на другой сертификат или Developer ID пользовательское разрешение может потребоваться заново.

## Создание репозитория

1. Создайте в своём GitHub пустой репозиторий, например `ControlFlip`.
2. Загрузите содержимое этого проекта, включая скрытую папку `.github`. В него должны попасть исходники, изображения, скрипты, VERSION и BUILD_NUMBER. Папки `.build`, `dist`, приложения, DMG и материалы подписи не загружайте в исходники.
3. В **Settings → Environments** создайте окружение `release`. В его **Environment secrets** добавьте три секрета:

| Имя | Значение |
|---|---|
| `SIGNING_P12_BASE64` | Содержимое `author.p12`, закодированное Base64 |
| `SIGNING_P12_PASSWORD` | Пароль из закрытого файла `password.txt`, без завершающего перевода строки |
| `SIGNING_CERT_SHA1` | Открытый отпечаток из `fingerprint.txt` |

Base64 не шифрует данные. Значение хранится именно в GitHub Secrets, не в файле репозитория, issue или сообщении чата. [Документация GitHub о секретах](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

GitHub Actions читает ключ из секретов на одноразовом runner, проверяет отпечаток сертификата и удаляет временные файлы после сборки. Связка ключей и системные настройки доверия не изменяются. На компьютерах пользователей этот процесс не выполняется. Проверки pull request не получают материалы подписи.

## Новый выпуск

1. Измените `VERSION`, увеличьте `BUILD_NUMBER`, обновите `RELEASE_NOTES.md` и сохраните изменения в GitHub.
2. Создайте и отправьте тег, совпадающий с VERSION, например `v1.2.3`.
3. Workflow **Prepare signed draft release** проверит ключ, соберёт Universal DMG и создаст черновик Release. Если секретов нет или подпись временная, выпуск остановится. Обычная проверка сборки DMG не публикует.
4. Скачайте DMG из черновика и проверьте первый запуск, исправление текста, исключения и автозапуск на обычном Mac.
5. До заявления о сохранении доступа без повторных запросов проверьте две разные версии, подписанные одним ключом: выдайте доступ первой, замените второй, убедитесь, что исправление работает и разрешение сохранилось. Сравнение подписей само по себе не доказывает состояние системного разрешения.
6. После проверки вручную опубликуйте черновик кнопкой **Publish release**.

Workflow можно повторно запустить вручную, выбрав соответствующий тег. Уже существующий Release не перезаписывается автоматически. Репозиторий: https://github.com/BezNik2006/ControlFlip. Первый готовый установщик доступен в Downloads по ссылке из README; GitHub Release для него ещё не создан. Подпись автоматических выпусков потребует настроить секреты окружения release. Локальная сборка уже проверена; запуск Actions проверяется отдельно в репозитории.

## Переход на Developer ID

При вступлении в Apple Developer Program можно заменить сертификат подписи на Developer ID Application и добавить нотариальное заверение и stapling. В `build.command` предусмотрен `SIGNING_STYLE=developer-id` для подписи с hardened runtime и timestamp, но текущий `release.command` нотариальное заверение не выполняет. Бесплатный workflow остаётся самоподписанным.

[Developer ID и нотариальное заверение — Apple](https://developer.apple.com/developer-id/).
